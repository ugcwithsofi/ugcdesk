# UGC Desk · установка через GitHub и Cloudflare Workers

Отправная точка — у тебя уже есть бот в Telegram, созданный через BotFather. Его код, кабинет, база и напоминания будут работать в Cloudflare. GitHub будет хранить код и передавать изменения на сборку. Тебе нужны браузер, аккаунты GitHub и Cloudflare, а также токен твоего бота. На компьютер ничего устанавливать не требуется.

## Если бот уже работает и ты обновляешься до 1.3

1. Распакуй ZIP и открой папку `ugc-cloudflare` внутри него. Там лежат обновлённые файлы.
2. Открой **существующий** репозиторий `ugc-desk` на GitHub. На вкладке **Code** проверь, что выбрана ветка **main** и виден `worker.mjs`.
3. Над списком файлов нажми **Add file → Upload files**. Перетащи в область загрузки содержимое новой папки `ugc-cloudflare`, включая `public`. Внизу нажми **Commit changes** и сохрани изменения в **main**.
4. В Cloudflare открой **Workers & Pages → ugc-desk → Deployments** и дождись успешной сборки. Затем вы оба отправьте боту `/start`, чтобы обновились кнопки внизу. Продолжай работать с тем же Worker и базой. Повторное подключение Telegram через `/setup` не требуется.

В Telegram открой **Сегодня → Добавить бренд**. Отправь email, затем название и выбери язык письма. Через **Сегодня → Следующий бренд** бот возьмёт в работу одну карточку. Скопируй email, отправь письмо в почте и нажми **Написал** или **Написала**. Email из старого CSV без даты отправки уже доступен в этой же очереди.

Дневная цель по умолчанию — 10 первых писем на человека. В **Сегодня** виден личный прогресс и задачи по проверке ответов. Первая проверка через три дня по умолчанию. После первого **Ответа нет** бот ставит повторную проверку через два дня. Если ответа по-прежнему нет, открывает черновик follow-up. После отметки об отправке follow-up бот напомнит ещё через три дня. Письма отправляются вручную.

## 1. Распакуй правильный архив

1. Скачай **UGC-Desk-Cloudflare-1.3.zip**. В Проводнике щёлкни по архиву правой кнопкой мыши и выбери **Извлечь всё**.
2. Открой папку `ugc-cloudflare` внутри распакованного архива. В ней должны быть `worker.mjs`, `wrangler.jsonc`, `package.json`, `pnpm-lock.yaml` и папки `public` и `test`. Это версия для Cloudflare.
3. Оставь эту папку открытой. Файлы из неё надо загрузить в GitHub. Токен в исходники, ZIP и GitHub вставлять не нужно. Для него будет отдельное поле в Cloudflare.

## 2. Загрузи код в GitHub

1. Войди в свой аккаунт и открой [создание репозитория](https://github.com/new).
2. В **Repository name** введи `ugc-desk`. Выбери **Private**. Включи добавление README, чтобы GitHub сразу создал ветку `main`. Нажми **Create repository**.
3. В открывшемся репозитории нажми **Add file → Upload files**.
4. Вернись в Проводник, открой `ugc-cloudflare`, выдели её **содержимое** через **Ctrl+A** и перетащи в область загрузки GitHub. Папки `public` и `test` тоже должны загрузиться. GitHub заменит пустой README инструкцией из архива.
5. Напиши сообщение коммита, например `Add UGC Desk for Cloudflare`. Сохрани изменения в `main`. Если GitHub предлагает новую ветку, создай её, открой pull request и объедини с `main`.
6. Проверь главную страницу репозитория. `wrangler.jsonc` и `worker.mjs` должны быть видны сразу. Если они оказались внутри лишней папки `ugc-cloudflare`, при подключении Cloudflare укажи её в поле **Root directory**. [Загрузка файлов в GitHub через браузер](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)

## 3. Запусти Worker

1. Открой [Cloudflare Dashboard](https://dash.cloudflare.com/) и войди в свой аккаунт. В меню найди **Workers & Pages**.
2. Нажми **Create application**, выбери **GitHub** и авторизуй приложение Cloudflare Workers & Pages. Если GitHub предлагает выбор репозиториев, выбери **Only select repositories** и разреши доступ к `ugc-desk`.
3. Выбери репозиторий `ugc-desk`. На экране сборки укажи:

   | Поле | Значение |
   | --- | --- |
   | Worker name | `ugc-desk`, как в `wrangler.jsonc` |
   | Production branch | `main` |
   | Root directory | Оставь пустым, если `wrangler.jsonc` лежит в корне |
   | Build command | Оставь пустым |
   | Deploy command | `pnpm exec wrangler deploy` |

   Если интерфейс предлагает предварительные сборки для других веток, можешь отключить их на первом запуске. Зависимости устанавливаются на стороне Cloudflare по файлу `pnpm-lock.yaml`. [Подключение нового Worker к GitHub](https://developers.cloudflare.com/workers/ci-cd/builds/#connect-a-new-worker)
4. Нажми **Save and Deploy**. Если Cloudflare предложит зарегистрировать поддомен `workers.dev`, задай свободное имя. Дождись успешной сборки и скопируй URL Worker из **Overview** или **Domains & Routes**. Он выглядит примерно как `https://ugc-desk.твой-поддомен.workers.dev`.
5. Открой URL. Должен появиться экран входа UGC Desk. По адресу `/health` ты увидишь `ok: true` и пока ещё `connected: false`. Это ожидаемо до подключения Telegram. База SQLite создаётся внутри Durable Object автоматически. Отдельный ресурс D1 создавать не нужно. [Хранилище Durable Objects](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)

## 4. Добавь токен и ключ настройки

1. Открой созданный Worker в Cloudflare. Зайди в **Settings → Variables and Secrets → Add**. Это настройки запущенного Worker. Раздел **Build variables and secrets** для этих значений не используется.
2. Выбери тип **Secret**. В **Variable name** впиши `BOT_TOKEN`, а в **Value** вставь токен от BotFather целиком.
3. Создай второй секрет `SETUP_KEY`. Сгенерируй в менеджере паролей случайную строку, например из 32 букв и цифр, и сохрани её у себя. Это ключ для страницы подключения. Он отдельный от токена.
4. Сохрани и нажми **Deploy**, если Cloudflare просит применить изменения. Ничего секретного в GitHub добавлять не нужно. [Как добавить секрет через панель Cloudflare](https://developers.cloudflare.com/workers/configuration/secrets/#via-the-dashboard)

## 5. Подключи Telegram и закрепи доступ

1. Добавь `/setup` к URL Worker и открой его в браузере. Например, `https://ugc-desk.твой-поддомен.workers.dev/setup`.
2. Вставь значение **SETUP_KEY** в поле **Ключ настройки** и нажми **Подключить Telegram**. Должно появиться **Подключено: @имя_бота**. Сверь, что указан именно твой бот. Страница сама регистрирует webhook, через который Telegram передаёт сообщения Cloudflare. [Telegram Bot API: setWebhook](https://core.telegram.org/bots/api#setwebhook)
3. Открой этого бота в личном чате Telegram, нажми **Start** и отправь `/id`. Он покажет твой числовой ID. Партнёрша делает то же со своего аккаунта и передаёт тебе свой ID. До назначения ролей рабочие карточки закрыты.
4. Вернись в **Settings → Variables and Secrets** и добавь два секрета:

   | Имя | Значение |
   | --- | --- |
   | `OWNER_TELEGRAM_ID` | Твой ID, только цифры |
   | `PARTNER_TELEGRAM_ID` | ID партнёрши, только цифры |

5. Примени изменения кнопкой **Deploy**. Подключать webhook повторно после изменения ID не нужно. Оба отправьте `/start`. У обоих должны появиться рабочие кнопки. **Импорт CSV** и **Код для кабинета** доступны владельцу.
6. После успешной проверки можешь удалить `SETUP_KEY` из Cloudflare и применить изменение. Бот продолжит работать. Если позже понадобится заново зарегистрировать webhook, добавь новый ключ и повтори подключение через `/setup`.

## 6. Проверь бота и кабинет

1. Со своего аккаунта отправь боту `импорт-пример.csv` как файл. Бот покажет предпросмотр. Нажми **Импортировать**. В файле вымышленные контакты.
2. Партнёрша отправляет боту `contact@example.com`. Должна открыться карточка **Example Bottle** со статусом **Ждём ответ**.
3. Партнёрша нажимает **Есть интерес**. Повторный поиск по email должен показать новый статус. При желании проверьте заметку из карточки.
4. Ты отправляешь боту `/login`, открываешь основной URL Worker и вставляешь одноразовый код. В кабинете открой **Проекты** и проверь карточку. Партнёрше команда `/login` должна сообщить, что кабинет доступен владельцу.
5. Закрой браузер. Бот должен продолжать отвечать. Проверки запускаются Cloudflare каждую минуту, время подборки берётся из настроек кабинета. Если после первого развёртывания расписание ещё не видно, открой **Settings → Triggers** и проверь, что подключён Cron Trigger `* * * * *`. Изменения расписания могут применяться с задержкой. [Расписание Cloudflare Workers](https://developers.cloudflare.com/workers/configuration/cron-triggers/)

Для реальной работы замени примеры в CSV своими данными. Обязательны столбцы `brand` и `email`. В `sent_at` указывай фактическую дату отправки, например `2026-11-08` или `2026-11-08T14:30:00+01:00`. В `assignee` ставь `owner` или `partner`. Без даты карточка остаётся на проверке. Максимум 2 000 строк и 1,5 МБ в UTF-8. При ответе бренда просто вставь в бота email отправителя.

## 7. Как потом обновлять код

1. Внеси изменения в файлы GitHub и сохрани коммит в `main`. Cloudflare запустит новую сборку. Проверить её можно в **Deployments → View build history**.
2. Используй тот же Worker `ugc-desk` и оставь привязку `DESK` и миграцию `v1` в конфигурации. Так обновления кода продолжат использовать существующую базу. Удаление Worker или хранилища может привести к потере данных.
3. Рабочие карточки не хранятся в GitHub. Для выгрузки открой **Настройки → Экспорт JSON** в кабинете. Экспорт нужен для чтения и переноса данных. Текущая версия не импортирует такой JSON обратно через интерфейс.
4. Для автопоиска брендов позже можешь добавить секрет `BRAVE_SEARCH_KEY` и настроить запросы в кабинете. Ручной CSV и Telegram работают без него.

## Если не получается

| Что видишь | Что проверить |
| --- | --- |
| Cloudflare не видит репозиторий | Убедись, что GitHub разрешил приложению Cloudflare доступ именно к `ugc-desk`. |
| Ошибка `Worker name mismatch` | Имя в Cloudflare должно совпадать с `name` в `wrangler.jsonc`. |
| Cloudflare не находит `wrangler.jsonc` | Проверь **Root directory** и расположение файлов в ветке `main`. |
| На `/setup` написано, что нужны секреты | Проверь `BOT_TOKEN` и `SETUP_KEY` в **Variables and Secrets** самого Worker, затем примени изменения. |
| На `/setup` не подходит ключ | Вставляй значение `SETUP_KEY`, созданное тобой, без кавычек и лишних пробелов. |
| Telegram вернул 401 | Сверь `BOT_TOKEN` с BotFather. Если токен менялся, обнови секрет и повтори подключение. |
| `/id` работает, а `/start` закрыт | Проверь два числовых ID и что новая версия с секретами уже активна. |
| Бот перестал отвечать после переноса на другой адрес | Зарегистрируй webhook заново с `/setup` на новом адресе. |
| CSV не открывается | Отправь его как файл с расширением `.csv` из аккаунта владельца. Сохрани в UTF-8. |

Для первого запуска достаточно пройти разделы 1–5. Затем проверь один импорт и поиск по email по разделу 6.
